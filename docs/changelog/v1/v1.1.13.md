# `@cldmv/git-embedded` v1.1.13 Changelog

**Release Date**: October 2026
**Release Type**: Patch
**Branch**: `release/1.1.13`

---

## Overview

Version 1.1.13 raises the declared Node.js floor to match its framework dependency and refreshes the lockfile. No file the package publishes changed: `bin/`, `src/`, `hooks/` and `messages/` are identical to [v1.1.12](./v1.1.12.md). The only `package.json` change is `engines.node`, which moves from `>=22.12.0` to `>=22.15.0` ([#104](https://github.com/CLDMV/git-embedded/pull/104)).

The lockfile moves two runtime dependencies, so this repository's own development and CI now run against newer copies of them: `@cldmv/slothlet` 3.21.0 → 3.22.0 and `@cldmv/wisp` 1.0.1 → 1.0.6. Both stay inside their existing ranges (`^3.7.0` and `^1.0.1`), and an install from npm resolves its own copies from those ranges regardless of this lockfile. The slothlet bump is the reason for the new floor: 3.22.0 raised its own `engines.node` from `>=22.12.0` to `>=22.15.0`.

The test suite also changed. Fourteen test files restored the environment with `process.env = originalEnv`, which breaks child-process environment inheritance from Node.js 26.11 and failed the Node.js 26 CI leg once it moved off 26.10. They now restore the variables in place ([#103](https://github.com/CLDMV/git-embedded/pull/103)).

## 🐛 Bug Fixes

### Node.js floor matches slothlet 3.22 ([#104](https://github.com/CLDMV/git-embedded/pull/104))

The package declared `>=22.12.0` while the `@cldmv/slothlet` range it depends on now resolves to 3.22, which needs `>=22.15.0` and cannot install its per-instance helper isolation on older 22.x releases. `engines.node` is now `>=22.15.0`, the CI minimum-Node default follows, and the README requirement reads "Node 22.15+".

### Test environment restored in place ([#103](https://github.com/CLDMV/git-embedded/pull/103))

Tests that replaced `process.env` wholesale broke the environment passed to spawned processes on Node.js 26.11 and later. All fourteen affected test files now delete the added keys and reassign the saved values onto the existing `process.env` object. Only tests changed.

## 🔧 Dependencies

All entries are lockfile-only updates within the existing `package.json` ranges.

### Runtime dependencies

- **`@cldmv/slothlet` 3.21.0 → 3.22.0** ([#99](https://github.com/CLDMV/git-embedded/pull/99)). A minor release of the module framework that composes the CLI's `src/api/` tree. It adds `api.slothlet.restart()`, an `around` hook type, host-controlled event delivery and typed `api` / `self` generation, none of which this package uses. Two changes can reach it: every module a leaf imports through a relative specifier is now loaded per slothlet instance (built on `module.registerHooks()`), and `engines.node` rises to `>=22.15.0` for that reason. The permission-related denies in 3.22.0 apply only when a permissions config is present, and this package configures none.
- **`@cldmv/wisp` 1.0.1 → 1.0.6** ([#101](https://github.com/CLDMV/git-embedded/pull/101)). The JSON loader the CLI uses to read `package.json` files (for the `version` command and the husky and simple-git-hooks detection). Versions 1.0.2 and 1.0.3 were tagged but never published to npm, so npm went from 1.0.1 straight to 1.0.5. The one runtime change in that span is in 1.0.4: errors thrown by `wisp` and `wispSync` now carry the underlying error as `cause`, with the same messages. Versions 1.0.5 and 1.0.6 changed development tooling, headers and CI only. The later 1.0.7, which changes how `fallback` and `validate` failures are handled, is not in this lockfile.

### Development dependencies

- **`@cldmv/vitest-runner` 1.5.1 → 1.5.3** ([#101](https://github.com/CLDMV/git-embedded/pull/101)). Version 1.5.2 moved the runner's `chalk` dependency to 6.0.1, and 1.5.3 raised its `engines.node` from `>=20.19.0` to `>=22.12.0`. The package already depends on `chalk` `^6.0.0` directly, so the lockfile now resolves a single `chalk` 6.0.1 for both and the runner's nested `chalk` 5.6.2 copy is gone. Version 1.5.3 also fixes the runner's CommonJS entry to fail with a clear `ERR_REQUIRE_ESM` message on a Node.js without `require(esm)`, and relicenses the runner under Apache-2.0.
- **`vitest` 5.0.2 → 5.0.3** ([#96](https://github.com/CLDMV/git-embedded/pull/96)), with `@vitest/coverage-v8`, `@vitest/mocker` and `@vitest/spy` at 5.0.3, and `vite` 8.3.1 → 8.3.2, `rolldown` 1.2.11 → 1.2.12 (with its platform bindings) and `@oxc-project/types` 0.151.0 → 0.152.0 in the lockfile. The transitive `why-is-node-running` moves 3.2.2 → 3.2.1 because 5.0.3 pins that exact version.
- **`eslint` 10.11.0 → 10.12.0** ([#97](https://github.com/CLDMV/git-embedded/pull/97)).
- **`globals` 17.12.0 → 17.13.0** ([#99](https://github.com/CLDMV/git-embedded/pull/99)).
- **`@cldmv/eslint-plugin-jsonv` 1.0.13 → 1.0.15, `@cldmv/jsonv` 1.1.1 → 1.1.3 and `@cldmv/prettier-plugin-jsonv` 1.1.0 → 1.1.3** ([#101](https://github.com/CLDMV/git-embedded/pull/101)). The `.jsonv` lint and format plugins; the releases in between update test expectations and CI.

## Upgrade notes

- No breaking changes and no change to the CLI, the hooks, the published files or the dependency ranges, but the declared Node.js floor rises, so it is not a pure drop-in on Node.js 22.12 to 22.14.
- **Node.js floor.** `engines.node` is now `>=22.15.0`. The `@cldmv/slothlet` range `^3.7.0` resolves on a fresh install to the newest 3.x, and slothlet 3.22 declares `>=22.15.0`, so on Node.js 22.12 to 22.14 slothlet reports that its per-instance helper isolation cannot be installed. Use Node.js 22.15 or later (any Node.js 24 or 26 release qualifies).
- Contributors need Node.js 22.15 or later; Node.js 20 cannot install the test toolchain.
